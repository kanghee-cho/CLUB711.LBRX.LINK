# CLUB711

GitHub Pages에 게시할 모임 공지 페이지입니다. 한국 날짜 기준 D-day, 회비 안내, 참가자별 월별 입금현황을 표시합니다. 본문 HTML과 외부 입금현황 JSON은 같은 비밀번호로 각각 암호화하며, CSS와 JavaScript만 평문으로 공개합니다.

## 준비

- Node.js 22 이상과 npm이 필요합니다.
- 별도 패키지 설치는 필요하지 않습니다.
- 아래 명령은 저장소 루트의 로컬 터미널에서 실행합니다.

## 파일 구성

| 경로 | 용도 |
| --- | --- |
| `private\club711.html` | 내용을 작성하는 원본 HTML. Git 추적 제외 |
| `private\payments.json` | 참가자와 월별 입금액을 수정하는 원본 JSON. Git 추적 제외 |
| `club711.html` | 암호화 명령으로 생성하는 게시용 HTML |
| `index.html` | Pages 기본 주소에서 게시용 HTML로 연결하는 진입 페이지 |
| `data\payments.json` | 암호화 명령으로 생성하는 외부 입금현황 JSON |
| `assets\styles.css` | 공개 스타일. 잠금 화면과 본문에서 함께 사용 |
| `assets\site.js` | 공개 본문 JavaScript |
| `assets\ledger.js` | D-day 계산과 입금 데이터 검증·합산 |
| `assets\unlock.js` | 비밀번호 입력과 HTML·JSON 복호화 처리 |
| `tools\encrypt.mjs` | 로컬 암호화 도구 |
| `test\` | 암호화·복호화, D-day, 입금 데이터 테스트 |

`private` 폴더는 Git에 올라가지 않으므로 새로 clone한 환경에는 원본이 없습니다. 별도로 보관한 원본 HTML과 JSON을 위 경로에 복원하세요. 두 원본 모두 안전한 별도 위치에 백업하세요.

## 작성 및 암호화

1. `private\club711.html`에 본문을 작성합니다. 보호해야 할 내용은 이 HTML 안에 넣습니다.
2. `private\payments.json`에서 참가자와 월별 입금액을 관리합니다. 스타일과 동작은 `assets`에서 수정합니다.
3. 터미널에서 다음 명령을 실행합니다.

   ```powershell
   npm run encrypt
   ```

4. 7자 이상의 비밀번호 또는 긴 암호문을 입력하고, 확인을 위해 한 번 더 입력합니다. 입력 내용은 숨기며 Enter를 누르면 인식된 글자 수만 `[7 characters]`처럼 표시합니다. 길이가 부족하면 바로 재입력받고, 확인값이 다르면 두 입력을 다시 받습니다. 비밀번호를 명령행 인자나 코드에 적지 마세요.
5. 게시용 `club711.html`과 `data\payments.json`이 생성됩니다. 두 파일과 `assets`의 변경 사항을 GitHub에 함께 올립니다.

최초 실행 전에는 게시용 HTML과 JSON이 없습니다. 생성된 파일을 직접 수정하지 말고, 원본을 수정한 뒤 다시 암호화하세요. 비밀번호를 바꿀 때도 같은 명령을 실행하고 새 비밀번호를 입력한 다음 두 결과 파일을 함께 게시합니다.

## 입금현황 업데이트

1. `private\payments.json`에서 해당 참가자의 `payments`를 찾습니다.
2. 해당 월의 금액을 **그 월에 배정할 누적 입금액**으로 변경합니다. 원 단위 정수이며 `0`은 등록된 입금액이 없다는 뜻입니다. `true`, `"20000"` 같은 불리언·문자열이나 음수는 사용할 수 없습니다.
3. `updatedAt`을 실제 확인 시각으로 변경합니다. 예를 들어 `"2030-01-05T21:00:00+09:00"`처럼 시간대가 포함된 ISO 형식을 사용합니다. 초기값 `null`은 아직 입금 내역을 등록하지 않았다는 의미입니다.
4. `npm run encrypt`를 실행하고 기존 비밀번호를 입력합니다.
5. 생성된 `club711.html`과 `data\payments.json`을 함께 커밋·푸시합니다. 방문자는 새로고침 후 비밀번호를 입력해 갱신된 현황을 확인합니다.

다음은 형식 설명을 위한 **일부 예시**입니다. 실제 원본의 참가자·월 키는 유지하고 금액만 바꾸세요.

```json
{
  "id": "member-example",
  "name": "참가자 예시",
  "payments": {
    "2030-01": 20000,
    "2030-02": 10000,
    "2030-03": 0
  }
}
```

한 달 금액을 여러 번 입금했다면 기존 금액에 추가 입금액을 합산해 적습니다. 여러 달을 미리 납부한 경우에는 각 월에 나눠 입력하세요. 원본의 모든 월 키가 필요하며, JSON에는 주석이나 마지막 항목 뒤 쉼표를 넣지 마세요.

| 항목 | 의미 |
| --- | --- |
| `version` | 데이터 형식 버전. 현재 `1` 유지 |
| `monthlyAmount` | 1인당 월 회비 |
| `months` | 납부 월 목록. `YYYY-MM` 형식의 연속된 오름차순 |
| `members[].id` | 참가자별 고유 ID. 중복 금지 |
| `members[].name` | 표에 표시할 이름 |
| `members[].payments` | 모든 납부 월에 대한 누적 입금액 |

월 회비 이상이면 **완료**, 0원 초과·월 회비 미만이면 **일부**로 표시합니다. 0원인 미래 월은 **예정**, 이번 달과 이전 달은 **미입금**입니다. 납부 기한을 임의로 정하거나 연체 여부를 판단하지는 않습니다.

모인 회비에는 실제 등록한 금액 전체를 합산합니다. 목표 달성률에는 각 월 회비까지만 반영하며, 초과 입금액을 다른 달로 자동 배분하지 않습니다. 참가자 수·월 회비·기간을 변경한다면 원본 HTML의 공지 문구도 함께 수정하세요.

웹페이지는 **조회 전용**입니다. 브라우저에서 입금 내역을 저장하거나 GitHub의 암호화 JSON에 평문 금액을 직접 입력하는 방식은 지원하지 않습니다.

## D-day와 모임 날짜

`private\club711.html`의 `id="event-date"`인 `<time>` 요소의 `datetime`을 기준으로 계산합니다. 모임 날짜를 변경할 때는 화면의 날짜 안내도 함께 수정한 뒤 다시 암호화하세요.

방문자의 기기 시간대와 관계없이 한국 날짜(`Asia/Seoul`)를 사용합니다. 모임 전에는 `D-숫자`, 당일에는 `D-DAY`, 이후에는 `D+숫자`로 표시하며, 열린 화면에서는 분 단위로 날짜를 다시 확인합니다.

## CSS·JavaScript 연결

원본 HTML에는 다음과 같이 연결합니다. 경로는 원본의 `private` 폴더가 아니라, 생성될 게시용 HTML의 위치를 기준으로 작성합니다.

```html
<link rel="stylesheet" href="assets/styles.css">
<script src="assets/site.js" type="module"></script>
```

HTML과 외부 JSON을 복호화한 뒤 원본 HTML 전체를 문서로 열기 때문에 인라인 JavaScript와 외부 JavaScript 모두 실행됩니다. 복호화된 JSON은 메모리에서만 표시에 사용하고 비밀번호는 저장하지 않습니다. **페이지 잠그기** 버튼은 페이지를 새로고침하고 다시 잠급니다.

## GitHub Pages 게시

1. 생성된 `club711.html`, `data\payments.json`, `assets`와 `index.html`, `.nojekyll`을 포함한 변경 사항을 저장소에 커밋하고 푸시합니다. `private` 폴더가 포함되지 않았는지 반드시 확인합니다.
2. GitHub 저장소의 **Settings → Pages → Build and deployment**에서 **Deploy from a branch**를 선택합니다.
3. 게시할 브랜치와 **/(root)**를 선택하고 저장합니다.
4. 배포가 완료되면 Pages 기본 주소에 접속합니다. `index.html`이 잠금 화면인 `club711.html`로 자동 연결합니다.

기본 게시 주소는 <https://kanghee-cho.github.io/CLUB711.LBRX.LINK/>입니다. `/club711.html`로 직접 접속해도 됩니다. `.nojekyll`을 통해 정적 파일을 그대로 게시합니다. GitHub Pages는 HTTPS로 접속해야 하며, 브라우저에서 JavaScript와 Web Crypto를 지원해야 합니다. 외부 JSON을 불러오기 때문에 HTML 파일을 더블클릭해서 여는 `file://` 방식은 사용하지 마세요.

입금현황을 열지 못한다는 안내가 나오면 `data\payments.json`이 게시되어 있는지, HTML과 JSON을 같은 비밀번호로 암호화했는지 확인하세요. JSON이 누락되거나 복호화에 실패하면 잘못된 0원 현황 대신 오류를 표시합니다.

## 공개 범위와 주의 사항

- 암호화는 AES-256-GCM과 PBKDF2-SHA-256 600,000회를 사용합니다. 비밀번호를 저장하거나 서버로 전송하지 않습니다.
- `private` 안의 HTML과 JSON은 평문입니다. 강제로 Git에 추가하거나 배포 파일에 포함하지 마세요. Git 추적 제외는 로컬 파일 자체를 암호화하는 기능이 아닙니다.
- 이름·개인별 입금액은 원본 JSON에만, 계좌번호·비공개 공지는 원본 HTML에만 작성하세요. 공개 CSS·JS·문서에 복사하지 마세요.
- CSS·JS·이미지·첨부파일은 별도로 암호화하지 않습니다. 외부 파일, 파일명, 주석에 비밀번호나 보호할 내용을 넣지 마세요. 숨겨야 하는 이미지·데이터는 원본 HTML 또는 암호화 대상 JSON 안에 포함해야 합니다.
- 로그인 서버가 없는 방식이라 암호화 파일을 내려받아 비밀번호를 반복 추측할 수 있습니다. 다른 곳에서 사용하지 않는 길고 무작위성이 높은 비밀번호를 사용하세요.
- 비밀번호를 아는 사람은 복호화된 HTML을 저장하거나 공유할 수 있습니다. 암호화는 복사 방지 기능이 아닙니다.
- 비밀번호를 변경해도 이미 내려받은 이전 파일이나 Git 이력의 이전 파일은 이전 비밀번호로 열 수 있습니다.
- 비밀번호는 페이지 링크와 별도의 안전한 경로로 전달하세요.
